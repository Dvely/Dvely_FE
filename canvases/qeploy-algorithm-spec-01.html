알고리즘 명세서

Decision Agent 작업 처리 알고리즘의 흐름도

알고리즘 시나리오

  1. 요청 수신. 사용자는 자연어만으로 생성·수정·배포·도메인·인프라를 요청한다. 별도 액션 칩은 두지 않는다.
  2. 프로젝트 확인. 선택된 프로젝트가 없으면 “먼저 프로젝트를 생성해 주세요.”를 안내하고 처리를 중단한다.
  3. 세션 저장. 요청을 chat_sessions에 저장하고 제목을 자동 생성한다. 내부 Agent 분기는 사용자에게 보이지 않는다.
  4. 의도 분류. Decision Agent가 코드를 / 배포 / 도메인 / 인프라 Agent로 라우팅한다. 중간 의도는 노출하지 않는다.
  5. preview 커밋. 코드 변경은 요청 단위로 preview 브랜치에 커밋한다. 승인 후에도 즉시 main에 반영하지 않는다.
  6. 미리보기. Docker 컨테이너에서 실제 설치·빌드·실행한다. 내부 패널에서만 접근하며 외부 preview URL은 기본 발급하지 않는다.
  7. 비코드 작업. 배포·도메인·인프라 요청은 코드 변경 없이 승인 통제로 넘긴다. (명세서 2장)
  8. 승인 On/Off. Chat Settings가 Off이면 승인창을 생략한다. On이면 한 줄 요약 승인창을 띄운다.
  9. 승인·거절. 거절 시 해당 작업을 종료한다. 승인 시 실행 대기 큐에 넣으며, 즉시 main/production에는 반영하지 않는다.
  10. 결과 저장. 실행 이력은 agent_runs, 미리보기는 preview_sessions, 승인 기록은 approvals에 저장한 뒤 다음 요청을 기다린다.
