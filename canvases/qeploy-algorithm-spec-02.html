알고리즘 명세서

배포 · 도메인 · 인프라 반영 알고리즘의 흐름도

알고리즘 시나리오

  1. 요청 수신. Decision Agent가 배포·도메인·인프라로 라우팅한 작업을 받는다. 의도는 승인창에 한 줄로만 보여준다.
  2. 배포 여부. 배포가 아니면 도메인 연결 또는 인프라 운영(재시작·리소스·환경변수)으로 분기한다.
  3. 배포 대상. 정적 프론트엔드는 GitHub Pages, 그 외는 개인 AWS/GCP로 배포한다.
  4. 클라우드 연결. AWS/GCP가 연결되어 있지 않으면 해당 설정을 비활성한다. 연결은 필수가 아니다.
  5. 배포 실행. Pages 또는 연결된 클라우드에 반영하고 결과를 deployments에 기록한다. 배포 시에만 PR·merge와 버전(v1, v2…)을 올린다.
  6. 실패 판정. 실패 시 쉬운 설명, 원인 로그 일부, 최선의 수정안 1개를 보여준다. 단순 실패 메시지만 보여주지 않는다.
  7. 재시도. 사용자가 수정안을 승인하면 재빌드·미리보기를 진행한다. 거절하면 해당 배포를 종료한다.
  8. 도메인. 기본 URL은 항상 제공한다. 서브도메인(예: cafe.qeploy.com)은 사용자가 이름을 지정하며 랜덤 생성하지 않는다.
  9. 연결 검증. 중복·사용 불가 도메인은 승인창을 열지 않는다. 커스텀 도메인은 DNS 확인과 HTTPS 검증 후 승인한다.
  10. 반영. 성공 시 Overview에 Live·버전·최근 이력을 갱신한다. 인프라 비용 증가·서비스 영향 작업은 승인 대상이며 Secrets는 숨긴다.
