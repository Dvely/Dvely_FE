1. 인증 및 프로젝트 시작

  1. ① 사용자는 GitHub OAuth로만 로그인합니다. AWS/GCP 연결은 필수가 아닙니다.
  2. ② 레포 생성 · 커밋 · PR · Pages · workflow 권한을 요청하며, 선택한 레포에만 접근합니다.
  3. ③ 빈 프로젝트 · ZIP 업로드 · GitHub 레포 불러오기 중 하나로 시작합니다.
  4. ④ 카드에 프로젝트명 · 상태 · Live URL을 표시합니다. 트래픽 분석은 표시하지 않습니다.

2. 자연어 요청 및 Docker 미리보기

  1. ① 사용자는 자연어만으로 생성 · 수정 · 배포 · 도메인 · 인프라를 요청합니다.
  2. ② 의사결정 Agent가 코드 / 배포 / 도메인 / 인프라로 라우팅하고, 한 줄 요약만 보여줍니다.
  3. ③ 컨테이너에서 실제 설치 · 빌드 · 실행합니다. 단순 정적 렌더링이 아닙니다.
  4. ④ 미리보기는 서비스 내부 패널에서만 접근하며, 외부 공개 URL은 기본적으로 발급하지 않습니다.

3. 버전 관리 및 승인

  1. ① 코드 · UI · 기능 변경은 반영 전 승인창을 띄웁니다. Chat Settings에서 승인 On/Off를 관리합니다.
  2. ② 코드 변경은 preview 브랜치에 요청 단위로 커밋하며, 승인 후에도 즉시 main에 반영하지 않습니다.
  3. ③ 배포 승인 시 “최신 승인 버전으로 배포할까요?”와 버전 · URL · 요약을 한 줄로 보여줍니다.
  4. ④ 도메인 · 인프라 · 비용 증가 작업도 승인 대상입니다. 사용 불가 도메인은 승인창을 열지 않습니다.

4. 배포 및 도메인 연결

  1. ① 정적 프론트엔드는 GitHub Pages가 기본 배포 경로입니다.
  2. ② AWS/GCP는 계정 연결 후 제공자 · 리전 · 리소스를 한 페이지에서 설정합니다. 미연결 시 비활성 표시합니다.
  3. ③ 실패 시 쉬운 설명 · 로그 일부 · 수정안 1개를 보여주고, 승인 후 재빌드 · 미리보기를 합니다.
  4. ④ 기본 URL, cafe.qeploy.com 서브도메인, 커스텀 도메인을 연결합니다. 서브도메인은 랜덤 생성하지 않습니다.

5. 인프라 운영 및 Overview

  1. ① 인프라 선택값에 따라 예상 월 비용을 표시하고, 예산 초과 시 경고합니다.
  2. ② 서버 상태 · 재시작 · 리소스 · 비용 최적화를 자연어로 요청합니다. 비용 증가 작업은 승인 대상입니다.
  3. ③ Preview/Production 환경변수와 Secret을 관리하며, 민감 값은 화면에 그대로 노출하지 않습니다.
  4. ④ Overview에 URL · 배포 상태 · 현재 버전 · 최근 이력을 보여줍니다. 트래픽 분석은 제외합니다.
