Qeploy 요구사항 정의서

요구사항ID 요구사항명 기능ID 기능명 세부사항 예외사항
A01 인증 및
GitHub 연동		 A01_B01 GitHub 로그인
  • 사용자는 GitHub OAuth로만 서비스에 로그인한다.
  • 로그인 후 서비스 세션과 GitHub 연동 상태를 분리 관리한다.
 GitHub 로그인은 필수이다. AWS/GCP 연결은 필수가 아니다.
A01_B02 권한 요청
  • 레포 생성·연결, 브랜치, 커밋, PR, merge, Pages, workflow 실행에 필요한 권한을 요청한다.
 사용자가 생성했거나 명시적으로 연결한 레포에만 권한을 사용한다. 선택하지 않은 레포에는 접근하지 않는다.
A01_B03 레포 연결·생성·해제
  • 기존 GitHub 레포 연결, 새 레포 생성 후 연결, 연결 해제를 제공한다.
  • 서비스 프로젝트와 GitHub 레포는 동일 객체가 아닌 병렬 객체로 관리한다.
 연결 해제는 프로젝트와 레포의 연결만 끊으며, 레포 자체 삭제는 Danger Zone에서만 처리한다.
A02 프로젝트 관리 A02_B01 프로젝트 목록
  • 카드형 UI로 프로젝트명, 상태 배지, 최근 수정일, Live일 때 URL을 표시한다.
  • 최근 수정순 정렬, GitHub식 상대시간 표기를 사용한다.
  • URL 클릭은 새 탭, 그 외 영역 클릭은 Overview로 이동한다.
 트래픽·방문자 분석은 표시하지 않는다.
A02_B02 새 프로젝트 생성
  • 빈 프로젝트로 시작할 수 있다.
  • 이후 기존 레포 연결 또는 새 레포 생성 후 연결을 선택한다.
 생성 직후 반드시 GitHub 레포와 동일할 필요는 없다.
A02_B03 ZIP 업로드
  • 기존 결과물을 ZIP으로 업로드해 프로젝트로 가져온다.
 ZIP 업로드 후에도 GitHub 레포 연결이 필요하다.
A02_B04 GitHub 레포 불러오기
  • 접근 가능한 레포 목록에서 선택 → 확인 후 프로젝트 목록에 추가한다.
  • 목록에는 기본적으로 레포 이름만 표시한다.
 동일 레포를 다시 불러오면 새 프로젝트로 추가되며, 휴지통 대화는 자동 복구하지 않는다.
A03 AI Workspace A03_B01 자연어 요청
  • 사용자는 자연어만으로 생성·수정·배포·도메인·인프라 작업을 요청한다.
  • placeholder: “원하는 작업을 자연어로 입력하세요.”
 별도 액션 칩은 제공하지 않는다. 내부 Agent 분기 과정은 사용자에게 보이지 않는다.
A03_B02 의사결정 Agent
  • 요청을 해석해 코드 / 배포 / 도메인 / 인프라·운영 Agent로 라우팅한다.
 의도 파악 결과는 중간 노출하지 않고, 승인창에 최종 한 줄 요약만 보여준다.
A03_B03 대화 세션
  • 세션 단위 저장, 이어가기, 새 대화, 삭제. 제목·수정시간, 최근순, 제목 자동 생성.
 삭제 시 확인 모달 없이 휴지통으로 이동한다. 7일 후 완전 삭제. 연결 프로젝트가 없으면 복구 불가.
A03_B04 오버레이 튜토리얼
  • 새 대화 최초 진입 시 1회 표시. 입력창·미리보기·승인·예시 메시지를 하이라이트한다.
  • 화면 클릭 시 닫히며, 물음표 아이콘으로 다시 볼 수 있다.
 단계형 튜토리얼이 아니며 닫기 버튼은 두지 않는다.
A04 Docker 미리보기 A04_B01 컨테이너 실행
  • 컨테이너 안에서 실제 설치·빌드·실행한다. 클릭·입력 등 실제 사용 테스트가 가능해야 한다.
 단순 정적 파일 렌더링이 아니다.
A04_B02 내부 전용 접근
  • 서비스 내부 미리보기 패널에서만 접근한다.
 외부 공개 preview URL은 기본적으로 발급하지 않는다.
A04_B03 수명·캐시
  • 프로젝트 또는 작업 세션 단위로 생성하고, 미사용 시 자동 종료한다.
  • 의존성·빌드·이미지 캐시를 활용한다.
A05 버전 관리 A05_B01 preview 브랜치 커밋
  • 코드 변경은 preview 브랜치에 요청 단위로 커밋한다.
 변경 승인 후에도 즉시 main/production에 반영하지 않는다.
A05_B02 PR·merge·버전
  • 배포 요청 시 PR 생성, main/production merge, 버전 번호 증가(v1, v2…).
A05_B03 버전 배포·롤백
  • merge 이력(버전, 해시, 요약, 일시)을 기준으로 특정 버전 배포·롤백한다.
A06 승인 기반 통제 A06_B01 개발/수정 승인 코드 수정, UI 변경, 기능 추가·삭제, 실제 변경 반영 전 승인창을 표시한다. Chat Settings에서 승인 On/Off를 관리한다. Off이면 승인창을 생략할 수 있다.
A06_B02 배포 승인 “최신 승인 버전으로 배포할까요?”와 함께 버전·환경·예상 URL·변경 요약을 한 줄로 표시한다.
A06_B03 도메인 승인 서브도메인/커스텀 도메인 연결·변경, DNS/HTTPS 실제 반영 전 승인한다. 중복이거나 사용 불가하면 승인창을 열지 않는다.
A06_B04 인프라 운영 승인 서버 재시작, 리소스·오토스케일 변경, 비용 증가 또는 서비스 영향 작업은 승인 대상이다.
A07 배포 A07_B01 GitHub Pages 배포 정적 프론트엔드의 기본 배포 경로로 GitHub Pages를 지원한다.
A07_B02 AWS/GCP 배포 개인 클라우드 계정 연결 후 한 페이지에서 제공자·리전·아키텍처·리소스·네트워크·DB 등을 설정하고 배포한다. 클라우드 미연결 시 해당 설정은 비활성 표시한다.
A07_B03 배포 실패 처리 실패 시 쉬운 설명, 원인 로그 일부, 최선의 수정안 1개를 보여준다. 승인 후 재빌드·미리보기를 진행한다. 단순 실패 메시지만 보여주지 않는다.
A08 도메인 A08_B01 기본 배포 URL 도메인 미연결 시에도 Pages/AWS/GCP 기본 URL로 접근할 수 있다.
A08_B02 qeploy.com 서브도메인 사용자가 원하는 이름을 입력하고, 중복이 없으면 연결 승인창을 표시한다. 예: cafe.qeploy.com 서브도메인은 랜덤 생성하지 않는다.
A08_B03 커스텀 도메인 사용자 보유 도메인을 연결하고 DNS 확인, HTTPS, 연결 검증을 수행한다.
A09 클라우드 인프라
운영		 A09_B01 예상 요금 인프라 선택값에 따라 예상 월 비용·항목별 비용을 표시하고, 예산 초과 시 경고한다. GitHub Pages 전용 프로젝트에서도 섹션은 숨기지 않고 비활성화한다.
A09_B02 자연어 운영 서버 상태·로그·장애 분석, 재시작, 리소스 조정, 비용 최적화, 불필요 리소스 정리를 자연어로 요청한다. 비용 증가·서비스 영향 작업은 승인 대상이다.
A09_B03 환경변수·Secrets Preview/Production 환경값, Secret 숨김, 변경 이력을 관리한다. 민감 값은 화면에 그대로 노출하지 않는다.
A10 Overview 및
설정		 A10_B01 Overview 대시보드 현재 URL(복사), 배포 상태(Live/Pending/Failed/Draft), 현재 버전, 최근 반영 3개, 최근 커밋, AI Agent·Settings·제거 진입점을 표시한다. 트래픽 분석, GA4, 방문자 그래프는 제외한다.
A10_B02 Project Settings General, Repository, Version & Release, Deployment Defaults, Domain & HTTPS, Cloud, Cost, Environment, Chat Settings, Danger Zone 10개 섹션을 제공한다. 팀/조직 권한, LLM 모델 선택, 개인 LLM API Key, 결제 연동은 본 범위에서 제외한다.
A10_B03 프로젝트 제거 기본은 Projects 목록에서만 제거한다. 선택 시 GitHub 레포 삭제, 클라우드 정리, 영구 삭제는 Danger Zone에서 경고 후 처리한다. 프로젝트 제거 시 대화는 공용 휴지통으로 이동한다.
