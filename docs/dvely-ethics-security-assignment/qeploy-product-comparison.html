기존 제품과의 비교
측정지표 기존 AI 웹 빌더 (v0 / Lovable) 본 프로젝트 (Qeploy)
편리성 채팅으로 화면을 바로 만들 수 있으나, 배포·도메인·저장소는 각각 다른 콘솔에서 이어 하는 경우가 많다. 로그인부터 계획·코드·프리뷰·GitHub·배포·도메인까지 한 화면 워크스페이스에서 이어진다.
기능성 LLM이 코드를 생성하고 프리뷰를 띄운다. 변경은 대화로 덮어쓰며 공식 승인 단계는 없다. 자연어 → 실행 계획 → 코드·프리뷰 생성 후 GitHub 반영. 배포·도메인·환경변수·인프라도 승인 대상이다.
사용성 생성 속도는 빠르나, 프로덕션 반영 여부를 사용자가 도구 밖에서 판단해야 한다. 승인 정책(코드 변경/배포 ON·OFF)으로 자동 반영 범위를 조절할 수 있어 실서비스 수정에 쓰기 쉽다.
통합성 생성 도구, GitHub, 호스팅, 도메인 설정이 제품마다 분리되어 워크플로가 끊긴다. 에이전트 채팅·승인·GitHub·배포·도메인·환경변수를 하나의 프로젝트 파이프라인으로 연결한다.
안전성 대화 한 번에 코드가 바로 바뀌어, 실서비스에 의도치 않은 변경이 반영될 위험이 있다. 실행 계획 승인과 작업 결과 승인을 분리해, 확인 없이 배포·도메인 변경이 나가지 않는다.
유지보수성 신규 화면 생성에 강하고, 이미 운영 중인 서비스의 수정·재배포는 보조적이다. 기존 저장소를 연결해 수정·프리뷰·재배포할 수 있어 운영 중인 웹서비스 유지보수에 맞다.
